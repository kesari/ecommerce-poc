# Scorer ambiguity repair and revised rerun protocol

Date: 2026-10-18. Evaluation revision: **2.1**, retaining protocol-version 2 JSON.

The scorer now accepts the independently verified equivalent repairs identified
by the first smoke. Required-action coverage is separate from correctness of a
complete in-scope plan. Supporting claims outside the independently established
reference set remain visible as unverified extras, rather than being described
as proven false statements. No broad prefix, casing or punctuation tolerance
has been restored.

## Matching and scope

The optional trusted `scoring_policy.mode: scoped_reference_v1` enables the
revised behavior. Without it the scorer retains strict historical set matching;
other pilot records have not silently acquired REST-specific aliases.

- `equivalences_applied` records the exact claim conversion and bound proof.
  Canonical and equivalent spellings count as one semantic claim.
- `satisfies_required_actions` establishes required action coverage. It does
  not excuse wrong runtime claims or inconsistent obligations.
- `satisfies_any_repair` additionally requires the expected in-scope obligations
  and absence of established contradictions or invalid claims. Wrong before/after
  values at approved method aliases remain contradictions, even when the answer
  also contains a correct canonical action.
- `extras_unverified` retains unmatched supporting and out-of-scope claims.
  They gain no verified evidence credit. Established contradictory in-scope
  statements remain explicitly flagged.
- Precision is labeled **reference overlap**. It is not a claim that every
  unmatched source fact is false. There is no correctness/cost composite.

The public prompt now specifies dotted baseline-source member names and
before-change contract identity for edges. Actions carry the old/new transition.
Broader recommendations outside an explicitly bounded task belong in a separate
`additional_recommendations` array. These are generic formatting/scope rules;
the prompt does not expose expected repairs or equivalence identifiers.
