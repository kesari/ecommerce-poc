Run the worked example

Scoring needs only Python. Running an assistant needs Node 22 and the pi coding helper.

1. Check the scorer

cd impact-study/harness
python3 -m unittest discover -s scoring -p 'test*.py'
python3 -m unittest discover -s run -p 'test*.py'

This runs 33 fast tests for matching, scoring, severity, validation, and aggregation. The TypeScript runner has 21 more tests via npm test in run/.

2. Score a measured answer

python3 scoring/score.py score \
  --ground-truth records/REST-001.json \
  --answer answers/runs/REST-001-pi-qwen3-coder-3.json

The report shows what the agent found, what it missed, and which extra findings were false positives. Hand-written examples under answers/examples/ are documentation and are refused by the scorer.

3. Ask what a contestant added

python3 scoring/score.py marginal \
  --ground-truth records/REST-001.json \
  --baseline answers/runs/REST-001-pi-qwen3-coder-1.json \
  --candidate answers/runs/REST-001-pi-qwen3-coder-3.json

Each finding unique to the candidate is marked right or wrong against the locked-in answer — the comparison this whole study exists to make: what does each assistant add that the others miss?

Optional: test an assistant yourself

The runner gives the assistant a private copy of the code, read-only search tools plus optional ready-made reference files, and scores the result. Assistants cover local Ollama models and Claude/Codex subscriptions. Fifteen locked-in scenarios live under records/.

cd impact-study/harness/run
npm ci --ignore-scripts
node run.ts --record REST-001 --runs 1

Run everything with node run.ts --record all --runs 1, or pick one assistant with --contestant pi-codex-scip. Answers written without searching are thrown out automatically.

Optional: start the e-commerce fixture

docker compose -f commerce-platform/compose.yaml up --build -d

Open the storefront at http://localhost:3000 or the BFF API documentation at http://localhost:8080/swagger-ui.html.

docker compose -f commerce-platform/compose.yaml down
