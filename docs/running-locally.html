Run portable offline checks

python3 -m unittest discover -s harness/scoring -p 'test*.py'
python3 -m unittest discover -s harness/run -p 'test*.py'
python3 -m unittest discover -s harness/verification -p 'test*.py'
python3 -m unittest discover -s harness/verification/discovery -p 'test*.py'
python3 -m unittest discover -s harness/verification/discovery/infra -p 'test*.py'

These five suites passed 254 checks from a fresh source export, including proof integrity, scoring mutations and paired analysis. They do not call a model or rerun the Java/Docker business scenarios; portable verification uses the retained execution evidence. The configured evaluation host also passed four historical replay checks, giving 258 Python checks in the checkpoint. Historical runner receipts retain original absolute path bindings: the replay suite is not portable to a fresh clone, and those immutable receipts should not be rewritten to make it pass.

Preflight a verified case

python3 harness/scoring/score_v2.py preflight \
  --record harness/records/v2/H01.json \
  --oracle-bundle harness/verification/discovery/frozen/H01-oracle.json \
  --trusted-oracle-sha256 963f62cb5e9c0ad7f741cd52c29fd9729e0b56b69dc800938ab5d9b3eacef32c \

This independently checks the full record, selected oracle digest and protected artifacts. It makes zero provider calls and does not fabricate a model answer.

Inspect the prepared campaign

Open the prepared campaign directory. conditions.json has paid_runs_authorized: false and a zero approved total. Its US$10 per-attempt cap is a proposed configuration, not permission to spend.

schedule.json contains 144 slots. pre-run-analysis.json reports them all as unrun. frozen-input-pins.json records the selected input digests; disabled-cli-check.json retains an actual authorization refusal before provider initialization.

Do not edit a frozen file in place or reuse a prior smoke allowance. Development changes require a new freeze; any approved total must retain its prior settled and unresolved exposure.

Run native runner checks on a configured host

cd harness/run
npm ci --ignore-scripts
npm test

The checkpoint passed 101 Node tests with no skips. The full suite requires Node 22.19 or newer, pinned fixture Git checkouts, installed native products and their generated indexes/daemons. A fresh monorepo clone does not contain those generated indexes and is not automatically a configured native evaluation host.

Native setup, exact source pins and product prerequisites and retained operation checks describe the configuration. The runner exposes read-only source/product operations, not a general agent shell.

Re-execute protected runtime proofs

Fresh business verification requires Java 21, prepared Maven dependencies, the web dependencies for browser-component checks, and Docker for Kafka/PostgreSQL/Valkey. Export pinned source into fresh temporary directories outside the source estate and study; keep protected tests and reviewer-selected digests separate.

These checks use unprivileged containers, cached dependency images, random loopback ports and verifier-owned cleanup. No administrator or privileged-container setup was required for the recorded runs.
