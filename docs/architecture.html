Gortex, Graphify, SCIP, and agents

They solve different parts of the same problem. That distinction matters more than their feature lists.

SCIP proves what the code says.

The compiler knows that two references point to the same Java name. That is the strongest proof for anything inside the code.

Gortex maps how services connect.

It joins who-calls-whom relationships: web clients, endpoints, event senders, and event receivers.

Graphify sketches the big picture.

It builds broad background context from code, documents, settings, and ideas, with a relatively simple setup.

Claude and Codex do the detective work.

They search, connect clues, understand business meaning, and explain the result — but they can only report what they actually looked at.

The setup we are testing

SCIP+Gortex+Git, docs, tests→Claude / Codex→Change report with proof

The assistant reasons; it is not the source of truth. Exact code proof, service connections, and business reasoning stay visibly separate in the final answer.

What would justify Gortex?

It must find critical REST, Kafka, schema, or cross-language consumers that SCIP plus intelligent agent search misses. If it cannot do that reliably, the extra graph layer is difficult to justify.
