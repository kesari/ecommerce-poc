Experiment design

Test each source of change-impact evidence independently, then ask whether the combined architecture earns its complexity.

Candidate architecture

Proposed change→Agent→Retrieval · SCIP · system graph→Evidence aggregation→Change contract

The study does not assume that a graph is inherently correct. An edge should be persisted only when traversing it materially improves a dependency or topology question that retrieval cannot answer reliably.

Independent contestants

ContestantExpected strengthExpected gap
Agent-onlySemantic and architectural reasoning; fresh local changesRecall depends on search decisions
Hybrid retrievalRelevant code, documents, history, and configurationSimilarity does not prove dependency
SCIPExact compiler-derived symbol structureRuntime contracts are not always symbol edges
GortexREST, event, schema, and service blast radiusGraph freshness and operating cost
GraphifyLightweight persistent structural contextInferred edges may not improve authoritative recall
CombinedCompiler truth plus topology, retrieval, and reasoningMust justify its total complexity

H1 · Compiler truth

SCIP should provide the highest-confidence symbol-level dependency evidence.

H2 · System topology

Gortex should improve recall for cross-service relationships that language indexes cannot represent.

H3 · Agent reasoning

Agents should explain business and architectural effects well but remain non-exhaustive alone.

H4 · Graph value

A broad graph must demonstrate marginal findings, not merely reproduce retrieval results.

H5 · Combined evidence

The best answer may aggregate different evidence sources with explicit confidence.

Decision gates

GateQuestion
Deterministic correctnessAre symbol and structural claims exact?
Incremental recallDoes topology find critical consumers missed by simpler approaches?
False-negative reductionAre critical misses materially lower?
Precision and provenanceCan engineers verify why every finding exists?
FreshnessDo uncommitted and newly changed relationships appear quickly?
Value versus costIs the marginal gain worth indexing, storage, daemons, and maintenance?

Fixture estate

The React and Java commerce system supplies the test surface: Account, Catalog, Basket, Inventory, Order, Payment, Shipment, BFF, Web, and local platform repositories. REST handles immediate user interactions; Kafka carries order, inventory, payment, and shipment state. Each service owns PostgreSQL data, while Valkey remains a non-authoritative cache.
