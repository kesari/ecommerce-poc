Architecture

Small services with explicit ownership, immediate REST responses where users are waiting, and events where workflows can continue independently.

System flow

Commerce Web→BFF→Account · Catalog · Basket · Order
Order→ Kafka →Inventory · Payment · Shipment→ Kafka →Order

Service boundaries

BoundaryOwnsMain interaction
AccountCredentials, refresh sessions, addressesREST
CatalogProduct data and active statusREST
BasketItems, coupon, totals, versionREST plus events
OrderQuotes, order aggregate, workflow stateREST plus Kafka orchestration
InventoryAvailable and reserved stockKafka
PaymentAuthorization attempts and outcomesKafka
ShipmentDelivery estimates and shipmentsREST plus Kafka

Data

Each service has its own PostgreSQL database and Flyway migrations. MyBatis keeps SQL explicit. Valkey accelerates reads but is never authoritative.

Reliability

Transactional outboxes, idempotent inbox consumers, retries, dead-letter topics, optimistic basket versions, and circuit breakers make failure behavior visible.

Observability

Actuator metrics flow to Prometheus, traces flow through OpenTelemetry to Jaeger, and services emit structured logs with correlation context.

Deliberate POC limits

One coupon and credit-card token payments only. No batch scheduler, refunds, guest checkout, production secret manager, multi-region topology, or Kubernetes deployment is included.
