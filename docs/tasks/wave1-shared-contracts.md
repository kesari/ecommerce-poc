# Wave 1 Shared Contracts - inventory, payment, shipment

Frozen before any Wave 1 task starts. These exact shapes appear in all three
task briefs. Order-service (Wave 2) consumes and produces the same contracts.

## Event envelope (fixture section 11.2)

Every Kafka message wraps its payload in this envelope. JSON, UTF-8.

```json
{
  "eventId": "evt_uuid_v4",
  "eventType": "inventory.reserved",
  "schemaVersion": 1,
  "occurredAt": "2026-08-23T12:02:31.442Z",
  "producer": "inventory-service",
  "correlationId": "ord_uuid",
  "causationId": "evt_uuid_of_command",
  "partitionKey": "ord_uuid",
  "payload": {}
}
```

Rules:
- `partitionKey` and `correlationId` are always the orderId.
- `eventId` is generated by the producer; consumers deduplicate on it.
- `causationId` is the eventId of the command that caused this event.
- Unknown payload fields must be ignored by consumers.

## Delivery estimate API (provided by shipment-service, consumed by Order)

```text
POST /api/v1/delivery-estimates
```

Request:
```json
{
  "postalCode": "560001",
  "itemCount": 3,
  "subtotalMinor": 260000
}
```

Response 200:
```json
{
  "fromDate": "2026-08-25",
  "toDate": "2026-08-27",
  "shippingChargeMinor": 10000,
  "currency": "INR"
}
```

Deterministic POC rules (no external providers):
- Metro prefixes `11, 40, 56, 60`: from = today+2, to = today+3.
- All other postal codes: from = today+4, to = today+6.
- Shipping charge flat 10000 minor INR.
- Validation: postalCode required, matches `[0-9]{4,10}`; itemCount >= 1;
  subtotalMinor >= 0. Violations -> 400 `INVALID_REQUEST`.
- Cached in Valkey under `shipment:estimate:{hash}` for 5 minutes per fixture
  section 12 (hash of the normalized request). Writes do not exist here, so
  TTL expiry is the only invalidation path.

## Conventions every service follows

- Transactional outbox: business state + outbox row in one PostgreSQL
  transaction; a poller publishes to Kafka and marks rows sent.
- Inbox: consumer inserts processed `eventId`; duplicates return without
  re-running business logic.
- Retry topics `<topic>.retry.1`, `.retry.2`, `.dlq` already exist in Kafka;
  exhausted retries go to the DLQ with error metadata.
- RFC 9457 problem responses with stable codes and correlationId for HTTP APIs.
- MyBatis XML mappers into immutable records behind repository ports; UUID type
  handler registered; `mybatis.mapper-locations` configured.
- Build: `JAVA_HOME=$HOME/.sdkman/candidates/java/21.0.10-tem ./mvnw verify`.
