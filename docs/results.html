Results

We gave five AI assistants the same four problems. Each assistant searched the same code with the same AI model — the only difference was its reference material. Here is what happened, in plain language.

The five assistants

All five are the same AI model (GPT-5.4) searching the same code with the same read-only file tools. The only difference is the reference material each one gets.

AssistantHarness nameWhat extra help it gets
Agent-onlypi-codexNothing. It searches the code file by file — the Claude / Codex investigator from the comparison page.
SCIPpi-codex-scipA precomputed list of every code component and where it lives — compiler-accurate truth.
Gortexpi-codex-gortexA precomputed diagram of which service talks to which, and over what contract — system topology.
Combinedpi-combinedThe SCIP list and the Gortex diagram together — the proposal's Candidate F: the full end-state stack in one assistant.
Graphifypi-graphifyA lightweight list of which services are wired to which (from configuration files) and which database tables each owns — broad context, cheap to build.

Every run is blind: each assistant works in an isolated copy of the code and never sees the frozen correct answer. Full run commands live on the Run it page.

Test 1: the renamed address field

A developer renames one address field, postalCode to postcode, in the account service. Nothing fails to compile — but every confirmed order starts shipping with a blank postcode, the delivery checker rejects them all, and no shipment is ever created. The customer sees nothing except an order that never arrives.

AssistantResult
Agent-only (3 tries, score 0.81)Found every downstream victim but missed the account service where the change happened — in 2 of 3 tries, including a miss that breaks production.
SCIP (3 tries, score 0.88)Found everything except one end-to-end test. Never missed anything that breaks production.
Gortex (3 tries, score 0.67)Found the downstream victims but missed the account service every single time. Gortex points downstream, away from the scene of the crime.
Combined (1 try, score 0.71)Same blind spot as Gortex alone. More reference material did not stack — on this run it diluted focus instead.
Graphify (1 try, score 0.85)Full house on systems and code, zero production-breaking misses. The lightweight list guided without distracting.

Test 2: the renamed delivery event

The order service renames the order.confirmed delivery event. Two services listen for it — shipment and basket. After the rename, confirmed orders create no shipment and baskets never check out.

AssistantResult
Agent-only (3 tries, score 0.91)Found all four affected systems in every run; every run missed the basket test, and two of three also missed one orchestrator component.
SCIP (3 tries, score 0.94)Best of the three. Found every system and every contract that matters.
Gortex (3 tries, score 0.93)Nearly identical — events are exactly what the map was built for. This is its home turf.
Graphify (1 try, score 0.70)Found every system and every code component but missed the event contract entirely — Graphify's index carries no topic edges, so on events it is genuinely blind.

Test 4: the renamed database column

The account database renames its postcode column. Saving or reading a delivery address breaks — again inside one service. Every assistant first named the column without its service prefix and missed the expected contract name; that was a flaw in our naming rules, now fixed, and the rerun below uses the fixed rules.

What we recommend

DecisionReason in one line
Adopt SCIPBest or tied score on all four tests, and the only assistant that never missed anything production-breaking (outside the shared naming miss).
Retest Gortex, don't reject itExcellent on events, the thing it was built for — but it repeatedly misses the service where a change originates.
Replicate Graphify before adopting itA strong 0.85 debut with zero production-breaking misses at the lowest reading cost — but a single run proves nothing yet.
Don't assume Combined is bestSCIP plus Gortex together scored 0.71 on the first run, below either index alone. More context diluted focus instead of stacking strengths.
Keep the free local model away from sign-offsSame question scores anywhere from 0.39 to 0.74 and it sometimes answers without searching. Fine for drafting.

One caution: only the address-rename test has been repeated three times; the rest are single runs. Repeat each test twice more before spending budget on the strength of these numbers.

Eleven more scenarios are frozen and waiting for runs — money decimals, basket versioning, coupons, delivery windows, login identity, two more event changes, two more internal refactors, and a second database change. They will show whether these patterns hold beyond the first four tests.
