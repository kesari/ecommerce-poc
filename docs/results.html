Results

We gave three AI assistants the same four problems. Each assistant searched the same code with the same AI model — the only difference was its reference material. Here is what happened, in plain language.

The three assistants

AssistantWhat extra help it gets
AloneNothing. It searches the code file by file.
With a code directoryA complete list of every code component and where it lives.
With a service mapA diagram of which service talks to which, and over what contract.

Test 1: the renamed address field

A developer renames one address field, postalCode to postcode, in the account service. Nothing fails to compile — but every confirmed order starts shipping with a blank postcode, the delivery checker rejects them all, and no shipment is ever created. The customer sees nothing except an order that never arrives.

AssistantResult
Alone (3 tries, score 0.81)Found every downstream victim but missed the account service where the change happened — in 2 of 3 tries, including a miss that breaks production.
With a code directory (3 tries, score 0.88)Found everything except one end-to-end test. Never missed anything that breaks production.
With a service map (3 tries, score 0.67)Found the downstream victims but missed the account service every single time. A map of who-talks-to-whom points away from the scene of the crime.

Test 2: the renamed delivery event

The order service renames the order.confirmed delivery event. Two services listen for it — shipment and basket. After the rename, confirmed orders create no shipment and baskets never check out.

AssistantResult
Alone (score 0.91)Found all four affected systems but missed one code component and one test.
With a code directory (score 0.97)Nearly perfect. Found every system, every contract, every test that matters.
With a service map (score 0.95)Nearly perfect too — events are exactly what the map is built for.

Test 3: the stricter postcode rule

Shipment tightens its postcode check to require at least 6 digits. Customers with shorter postcodes can no longer get a delivery estimate — and it all happens inside one service, so this test checks whether assistants cry wolf about other services.

AssistantResult
Alone (score 0.89)Correct: one service affected, correctly identified.
With a code directory (score 0.89)Same correct answer, with exact file-and-line evidence.
With a service map (score 0.89)Same correct answer.

Test 4: the renamed database column

The account database renames its postcode column. Saving or reading a delivery address breaks — again inside one service. All three assistants found the service but named the column without its service prefix, so none matched the expected contract name. That was a flaw in our answer key's naming rules, now fixed — not a failure of searching.

AssistantResult
Alone (score 0.60)Right service, right area, wrong contract name.
With a code directory (score 0.60)Same — the directory lists code, not database columns.
With a service map (score 0.64)Same naming miss, slightly fewer extra guesses.

What we recommend

DecisionReason in one line
Adopt the code directoryBest or tied score on all four tests, and the only assistant that never missed anything production-breaking (outside the shared naming miss).
Retest the service map, don't reject itExcellent on events, the thing it was built for — but it repeatedly misses the service where a change originates.
Keep the free local model away from sign-offsSame question scores anywhere from 0.39 to 0.74 and it sometimes answers without searching. Fine for drafting.

One caution: only the address-rename test has been repeated three times; the rest are single runs. Repeat each test twice more before spending budget on the strength of these numbers.
