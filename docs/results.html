Results

We gave five AI assistants the same problems. Each assistant searched the same code with the same AI model — the only difference was the extra files each one could read. Here is what happened.

The five assistants

All five are the same AI model (GPT-5.4) searching the same code with the same read-only file tools. The only difference is the extra files each one gets.

AssistantHarness nameWhat extra help it gets
Agent-onlypi-codexNothing. It searches the code file by file — the Claude / Codex investigator from the comparison page.
SCIPpi-codex-scipA precomputed list of every code component and where it lives — compiler-accurate truth.
Gortexpi-codex-gortexA precomputed diagram of which service talks to which, and over what contract — system topology.
Combinedpi-combinedThe SCIP list and the Gortex diagram together — the proposal's Candidate F: the full end-state stack in one assistant.
Graphifypi-graphifyA lightweight list of which services are wired to which (from configuration files) and which database tables each owns — broad context, cheap to build.

Every run is blind: each assistant works in an isolated copy of the code and never sees the correct answer, which we wrote down before testing. Full run commands live on the Run it page.

Test 1: the renamed address field

A developer renames one address field, postalCode to postcode, in the account service. Nothing fails to compile — but every confirmed order starts shipping with a blank postcode, the delivery checker rejects them all, and no shipment is ever created. The customer sees nothing except an order that never arrives.

AssistantResult
Agent-only (3 tries, score 0.81)Found every affected downstream service but missed the account service where the change happened — in 2 of 3 tries, including a miss that breaks production.
SCIP (3 tries, score 0.88)Found everything except one end-to-end test. Never missed anything that breaks production.
Gortex (3 tries, score 0.67)Found the affected downstream services but missed the account service every single time. Gortex points downstream, away from where the change happened.
Combined (1 try, score 0.71)Same blind spot as the Gortex-only run. More extra files did not help — on this run it diluted focus instead.
Graphify (1 try, score 0.85)Found every affected service and code item, with nothing missed that breaks production. The lightweight list guided without distracting.

The bottom line

Fifteen tests, one shared model, five reference setups. No assistant wins everywhere: SCIP leads where the owning service hides, Gortex wins coupons and events, Agent-only wins the timestamp reshape, and Graphify ties the easy ground cheaply while going blind on events and contracts. The free local model is disqualified on consistency long before quality is debated. The decision from the first four tests stands, and the eleven new tests sharpen it rather than overturning it: buy SCIP, keep Gortex for events, and never let an unsearched answer near sign-off.

What we recommend

DecisionReason in one line
Adopt SCIPBest or tied on six of the nine tests it ran, and the only assistant that never missed anything production-breaking outside shared naming misses — but it lost the coupon and timestamp tests outright.
Retest Gortex, don't reject itExcellent on events, the thing it was built for — but it repeatedly misses the service where a change originates.
Replicate Graphify before adopting itA strong 0.85 debut with zero production-breaking misses at the lowest reading cost — but a single run proves nothing yet.
Don't assume Combined is bestSCIP plus Gortex together scored 0.71 on the first run, below either index alone. More context diluted focus instead of stacking strengths.
Keep the free local model away from sign-offsSame question scores anywhere from 0.39 to 0.74 and it sometimes answers without searching. Fine for drafting.

One caution: only the address rename and the topic rename have been repeated three times; the rest are single runs. Repeat each test twice more before spending budget on the strength of these numbers.

All fifteen locked-in scenarios now have at least Graphify coverage, and the trio has run nine of them. The remaining gap is trio replication on the six newest event, internal, and database tests.
