If I change this, what else breaks?

We built a small e-commerce system to compare four ways of finding change impact across repositories.

The idea

The shop is not the product. It is realistic test data: separate services connected through Java code, REST APIs, Kafka events, schemas, and a React client.

We make one change, ask each approach what will be affected, and compare its answer with a frozen correct answer.

The four approaches

ApproachThink of it asBest at
SCIPA compiler-accurate mapExact code definitions and references
GortexA map of service communicationREST, Kafka, schemas, and blast radius
GraphifyA broad, lightweight graphQuick visual context across code and docs
Claude / CodexAn investigatorSearching, reasoning, and explaining meaning

Why one approach is not enough

SCIP: code truth+ Gortex: system map+ Agent: reasoning

Graphify is the lightweight control. It helps us test whether a simpler graph provides enough value before adopting a specialized system graph.

A change that looks small

Account renames postalCode to postcode.

Account JSON→Order gets null→Kafka carries null→Shipment DLQ

Shipment does not directly reference Account's field. Finding that transitive failure is the point of the POC.

First results

Same model, same question, three runs each: agent-only averages 0.81 with critical misses in two runs, the symbol index 0.88 with none, the contract graph 0.67 — see the scores.
